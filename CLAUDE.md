# Portfolio implementation notes

## Current design

This is an explorable island portfolio, built with Next.js 14, React 18, TypeScript, React Three Fiber 8, Drei 9, and Three.js. Keep dependency upgrades coordinated with the React version. Install with `npm install --legacy-peer-deps`.

Visitors scroll down/up between sections, orbit and zoom within an area, select places from a map, and deliberately open readable content from small objects. Ordinary wheel input belongs to section navigation; it must never zoom the camera. The section order is circular: a forward step from the final west shore returns to the overview, while a backward step from the overview returns to the west shore. Zoom uses pinch, explicit buttons, or the focused canvas keyboard controls. The scene is one viewport; there is no document-sized camera track. Keep physical objects at their measured scale and avoid shoreline billboards or an invisible multi-viewport scroll container.

`docs/ISLAND_EXPLORATION.md` records the inspected scene, measured anchors, design decisions, and acceptance checks. `README.md` contains run/check commands.

## Ownership and data

- `app/portfolio-data.ts`: factual content. Preserve claims and destinations; do not invent project links or metrics.
- `app/components/island-data.ts`: `AREAS`, `TOUR`, responsive camera helpers, and shared types. `ReadRequest` uses stages 1 About, 2 Engineering, 3 Projects, 4 Career, 5 Contact, 6 Lagoon systems log, and 7 West-shore infrastructure board. Career `item` values are chronological: 0 education, 1 internship, 2 senior role. `source: 'door'` distinguishes the bungalow note from the current-role hammock card.
- `IslandScene.tsx`: navigation, atmosphere, reader state, loading suspension, and Canvas lifecycle.
- `SceneWrapper.tsx`: server-rendered loading shell and client-only scene import. Wait for scene preparation and `document.fonts.ready`; expose the canvas beneath the departing loader, then enable the interface and arrival only after its exit completes. Keep the viewport inert until that completion.
- `LoadingScreen.tsx` / `LoadingArtwork.tsx` / `loading-progress.ts` / `loading-screen.css`: illustrated arrival screen with CSS-only transform/opacity animation on composited HTML layers. Never restore a per-frame JS progress loop, animated SVG strokes, or inherited progress custom property. Asset progress occupies 0–90%; renderer/font readiness permits 100%. The bar eases independently, with no numeric counter to jump after main-thread work. Preserve one-shot transition/timeout completion, errors with `/read` access, and immediate Still/reduced-motion behavior.
- `SceneReadiness.tsx` / `scene-readiness.ts`: upload unique visible textures in batches with a 4 ms CPU budget, then compile against the actual composer render target and restore the previous target before awaiting completion. Canvas remains at `never` until compilation, then warms three demand-rendered frames before reporting ready. The compositor prepares its overview blur at zero mix while covered, and continuous rendering starts only after the loader exits. Cancel stale generations and frame callbacks on pause, unmount or Strict Mode effect replay. Camera setup must establish the arrival origin or skipped-intro overview beneath the loader while exploration input remains disabled.
- `IslandDayCycle.tsx` / `day-cycle.ts`: one eased, approximately two-second blend drives scene background/fog, ambient/hemisphere/directional colours and intensities, sky, water, emissive accents and selective bloom. Reverse from the current value without snapping. Pause/resume the blend with the scene; Still and system reduced motion switch instantly.
- `IslandSky.tsx` / `island-sky.ts`: persistent gradient dome with six low-poly clouds, independent of first-visit arrival/session state. The clouds use three joined geometries from `cloud-geometry.ts`, instanced into six banks in three draw calls with opaque, smooth-normal materials; 170 stars and a small crescent moon fade in at dusk. World-oriented clouds drift on one accumulated clock; freeze under Still/reduced/pause and clamp resume delta. Cloud surfaces write depth so their backs and distant stars do not bleed through. The sun halo stays behind the ocean at -11. Frozen cloud clocks update colour without re-uploading instance matrices. Persistent clouds use neither procedural noise nor sprites; `cloud-texture.ts` belongs only to the temporary `ArrivalClouds` layer.
- `IslandWater.tsx` / `island-water.ts` / `water-depth.ts`: one two-triangle ocean at y=2.08 replaces the flat plane and cloned GLTF transmission-water mesh. Bake sand depth and signed shore distance once into a 256px texture; never render another scene/depth/reflection pass for water. Extend only seabed heights offshore, not rock heights, and fade transparency before the finite model edge. Caustics patch owned sand materials and restore their compile hooks on cleanup. All water/caustic animation shares one clock frozen under reduced motion, Still and pause. Mobile compiles two ripple layers. Preserve underwater fish and skip water raycasting.
- `IslandLighting.tsx` / `island-rendering.ts`: shadow fitting uses only the actual island, with wind padding, never the ocean plane. Desktop maps are 2048 and phone maps 1024. Sustained phone frames above 29ms disable shadows until reload; exclude loading, readers, hidden tabs and demand rendering from the measurement. Coarse touch devices retain this budget in landscape.
- `IslandPostprocessing.tsx`: lazy-loaded desktop composer (RPP 2.19.1 for React 18). Keep AO gentle and bloom selection restricted to tagged dusk light meshes, with intensity driven by the shared day cycle. Tilt-shift is confined to overview and capped at 0.035 to retain sky detail. Readers disable the whole composer without reallocating its targets. Release owned passes/targets on unmount, preserving Strict Mode effect replay. Canvas uses Three r184’s supported PCFShadowMap constant; the deprecated PCFSoftShadowMap alias has identical filtering but logs and resets the setting repeatedly.
- `section-scroll.ts`: one section per deliberate wheel gesture, with momentum consumption and blocked reader input. Allow a new gesture to retarget an active flight; do not lock scrolling for the flight duration.
- `IslandControls.tsx`: sole camera owner. OrbitControls uses short damping during exploration, no panning, and clears inertia before flights, collision rollback and reading. A drag cancels an area flight immediately without clamping the current pose outward. Browser-height changes adjust the lens without starting a new journey. Reading approaches lock orbit/navigation and support Escape or an explicit cancel button. Keyboard exploration controls operate only while the canvas is focused.
- `island-arrival.ts` / `ArrivalClouds.tsx`: first-reveal policy and temporary cloud sprites. The same controller prepares a guarded high-altitude route under LoadingScreen and plays it for 3.5 seconds after reveal. Any pointer, touch, click, wheel, or keyboard input skips to overview. Reduced motion, session-persisted Still, and `sessionStorage['island-arrival-seen']` suppress the introduction. If the guard cannot route safely, skip. The welcome heading's letters animate only during this arrival, with a single accessible name; returning home must never replay them.
- `artifact-camera.ts` / `artifact-motion.ts`: eleven measured reading poses and shared reversible camera motion. `magazine-camera.ts` supplies the magazine's page basis.
- `camera-path.ts`: static-model guard and travel routing. Maintain the endpoint and route checks when changing navigation.
- `WorldArtifacts.tsx` and `artifact-textures.ts`: physical object construction and concise printed invitations.
- `ArtifactInvitations.tsx` / `artifact-beacon.ts`: one shared prewarmed amber beacon texture, constant-screen-size targets (48px phone / 52px desktop), bounded BVH occlusion, desktop labels and calm opacity motion. Keep sprites mounted at zero opacity before shader preparation, then hide inactive ones. No per-frame allocations or demand-frame invalidation. Gate cues during travel, intro, focus, readers, guides and hidden tabs. Visibility rays end at the cue (margin 0), never behind it in its supporting table/wall. Keep cues off noninteractive decorative objects.
- `artifact-hover.ts`: desktop mouse feedback for `Selectable`. Cache the artifact's local center, owned emissive material clones, and depth-tested warm glow shells once. Reuse original geometry/textures and exclude shells from raycasting. Frame updates only mutate cached numbers, vectors and colors; no traversal or allocations. Scale exactly 2% around the artifact center and restore immediately before reading, on disable, or on touch input. Coarse pointers and phone layouts create no hover resources; Still uses immediate feedback.
- `LivingIsland.tsx`: immutable source-model clone, material ownership, ambient pivots, phase-shifted palm-leaf wind, daylight motes, and optional Nessie discovery. Emissive light materials, fireflies, embers and the sun halo blend with the shared day cycle.
- `ArtifactReader.tsx`: native reading dialog, keyboard tabs, focus restoration, and confined scrolling. `FieldLogContent.tsx` supplies the lagoon and west-shore field-note editions; keep short-phone captions and reader actions visible for both. No camera or smooth-scroll imports.
- `FieldGuide.tsx` / `PortfolioContent.tsx`: complete reading content, also rendered at `/read` without the island.
- `exploration.css` / `artifact-reader.css`: scoped scene and reader styles imported from `globals.css`.

GSAP and Lenis remain installed dependencies, but the current island navigation does not use them. The retired `ScrollSetup`, `CameraJourney`, and `GlobalNav` components are not part of the architecture.

World prints use real mesh surfaces and textures. DOM reading size must not determine physical object size or camera distance. Reading opens explicitly, freezes the scene, and returns to the previous exploration pose.

## Camera constraints

Keep a stable world-up direction and broad neighborhood framing during exploration. Edit area poses, targets, distance limits, and orbit arcs in `island-data.ts`. Portrait framing adjusts field of view as well as distance. Explicit reading approaches use each printed surface's local up direction and interpolate camera quaternions. Do not call OrbitControls.update during these approaches: its cached world-up and exploration constraints would override the reading orientation.

The guard copies selected house, cabin, pier, terrain, rock, bush, and foliage triangles into an owned world-space BVH. Do not build an index-reordering BVH on shared GLTF buffers. Its weak cache follows the scene model lifetime; the collision geometry is CPU-only and is never rendered. Travel tries a direct segment, then inner/outer graph routes with a heading cost to discourage reversals. Each corner gets a local quadratic curve matching its adjacent segment directions. Accept paths only after offset-ray and sampled-clearance checks; do not fall back to a sharp polyline. Unroutable trips fade to the destination. Orbit movement is rejected if the camera passes below y=2.9 or a tested segment/endpoint is obstructed.

The guard is not complete camera-volume collision detection. Added geometry is not automatically in its static model whitelist. Check the visible framing and relevant orbit envelope whenever poses, materials, or geometry change.

## Model and material rules

`public/island.glb` is the preserved original by Jef Belmans. The app uses `island-optimized.glb`; regenerate it with `scripts/optimize-island.mjs` and its documented external tooling.

The model has baked vertex positions and scaled ancestors. Compute world bounds or inspect vertices when locating a prop; `getWorldPosition()` alone may report an origin rather than the visible center. Move animated semantic nodes under measured pivots instead of rotating a shared material mesh around the origin. In particular, the satellite dish shares a mesh with house details.

Only the scene clone receives the two measured fern offsets near the chalkboard. Cached geometry/textures belong to `useGLTF`; dispose only resources created by the component, including cloned materials and generated print textures.

`M_Plants`, `M_PalmTreeLeaves`, and `M_Torch` atlases contain RGB data without alpha. Their opaque cards are a known source-asset limitation. Raising `alphaTest` cannot recover missing alpha; do not guess destructive color-key masks or remove the canopy to conceal it.

## Interaction and lifecycle

- Sound starts only after an explicit toggle.
- Mobile settings are a header disclosure; keep the footer transparent. Phone map destinations use a named list with 44px targets. Keep antialiasing at capped DPR 1, skip R3F hover raycasts for touch/pressed-pointer moves, and omit floating Html labels on phones. Surface-anchored invitation sprites remain tappable, using bounded BVH visibility checks and the same action as their physical object. The area's reading action and physical-object taps remain available.
- Palm leaf crowns use owned local pivots with small phase-shifted gusts; never rotate the shared source model or a trunk with a leaf. Daylight adds a soft sun halo and sparse motes; dusk fades in fireflies and ember flicker. Water highlights belong to the water shader. Fish, gulls, hammock/cards, and fire flicker stop or simplify under reduced motion. The user can also choose Still; system reduced motion takes precedence.
- Pause rendering and animation while the tab is hidden or a reader is open. Use accumulated active time to avoid return jumps.
- Water depth lookup texels must settle to `DEPTH_MIN` before the outer perimeter. Clamping a shallower edge reveals the square texture boundary against open ocean. `check-island-water.cjs` checks two perimeter rings; `check-island-sky.cjs` checks persistent drift, pause/resume, palettes and resource cleanup.
- Keep every atmosphere consumer on the shared day-cycle value rather than independent timers. `check-day-cycle.cjs` covers blend timing, reversal from the current value, pause/resume and instant Still/reduced-motion switching.
- Preserve native dialog focus containment, Escape behavior, focus restoration, and normal internal scrolling. Every reading object uses approach → reading → closing → return. Capture the actual camera position, quaternion, up, target, field of view, and orbit limits; reveal the reader only after arrival. Retrace the travelled route on close or cancellation, restore the saved view, and avoid a second flight to the area's default pose. A cancellation before the first animation frame should simply clear focus state.
- Keep the scene and exploration UI inert through the entire reading sequence. Preserve mounted object invitations so DOM focus can return after the camera does. Block wheel section changes during approach/return, but keep normal internal reader scrolling. Still and system reduced motion skip both travel and reader animation. If an arbitrary exploration pose has no safe approach, open content in place rather than teleporting.
- Keep `/read`, named area buttons, and keyboard navigation usable without finding a tiny 3D target. The seven-Nessie trail is optional.

## Verification

Run `npm run lint`, `npx tsc --noEmit`, `node scripts/check-section-scroll.cjs`, `node scripts/check-magazine-camera.cjs`, `node scripts/check-artifact-cameras.cjs`, `node scripts/check-island-navigation.cjs`, and `npm run build` for relevant implementation changes. Production output is `.next-production`, separate from development `.next`.

`node scripts/check-mobile-camera.cjs` exercises the real controller and OrbitControls with a synthetic render loop: viewport resizing during orbit/travel, close-range interruption, inertia isolation, gradual zoom, collision rollback, and Still. It is a behavior regression check, not a phone GPU benchmark.

`node scripts/check-island-arrival.cjs` checks four actual-model arrival routes, loader timing, repeat/Still overview setup beneath the loader, interruption, navigation handoff, session policy, blocked storage, reduced motion, pause/resume, and a late model. Verify fresh-tab playback, reload skip, the letter reveal, and input-to-skip in the browser as well. Use a fresh browsing session to preview the introduction again; do not add a production replay bypass.

`node scripts/check-loading-lifecycle.cjs` exercises the actual loader/readiness hooks with a deterministic clock: zero-RAF loader motion, monotonic progress, Strict Mode effect replay, error gates, transition/timeout completion, Still/reduced motion, batched texture uploads, compiler target restoration, failures, pause/resume and presentation callbacks. `node scripts/check-scene-readiness.cjs` verifies the underlying generation and rendered-frame gate. These scripts do not measure GPU compilation or browser paint; also inspect first-load, cached-load and error handoffs in the browser.

`node scripts/check-artifact-hover.cjs` checks mouse/touch gating, eased 2% scale, an off-origin transformed pivot, warm material isolation, non-selectable glow geometry, stable frame resources, reduced motion, and cleanup/remount. Check the visible highlight and an actual mesh click in the browser after changing hover rendering.

The geometry script checks static endpoints and all 288 ordered area routes at desktop, two portrait sizes, and a narrow landscape size. It independently samples clearance along each returned path. It does not replace browser verification: visit all map areas, interrupt travel, inspect near buildings/palms, test mobile readers and keyboard tabs, close dialogs with Escape, and exercise reduced motion and loading fallback. Report the checks actually performed rather than treating a successful build as visual acceptance.

`node scripts/check-artifact-beacons.cjs` verifies fixed screen size, eased reveal, bounded visibility rays, occlusion, stable frame resources, inactive/Still states, and 40 real-model views. Also click a beacon in the browser on desktop and a phone-sized viewport and verify the correct reader, return and keyboard label focus.
